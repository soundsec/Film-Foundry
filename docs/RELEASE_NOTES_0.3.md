# Film Foundry v0.3.1 Alpha

v0.3.1 是基于 v0.3.0 的稳定性、兼容性和通用性能维护版本。它仍然是面向创作和可解释调节的物理启发式虚拟暗房，不是经过实物全面标定的光化学仿真器，也不承诺模拟某一款商业胶卷或扫描仪。

## v0.3.1 维护更新

- 收紧统一材料状态转换。
- 扫描器优化：负片与正片共享透射采集，去片基与反相由用户分别控制。
- 优化了显影冲洗扫描过程中的性能问题，修正了部分中间量重复计算问题。
- 改善颗粒、染料云、高光光晕、残银和冲洗事故的阶段归属与极端参数稳定性，并保持固定种子的可重复输出。
- 完整流程、只冲洗和只扫描现在会在运行清单中记录逐项成功、失败、输出位置和耗时。
- 优化了结果保存，以时间为标签分离储存，避免错误操作导致同名文件的覆盖问题。
- 修复部分竖向图片的 EXIF 方向不一致、重复输出覆盖、批次故障隔离。
- 修复打包便携版在特殊目录或中文路径下的启动问题。

## v0.3 系列主要能力

### 统一的银盐形成流程

- 彩色/黑白负片与彩色/黑白反转片共享材料池和有序处理算子。
- 负片、正片、反转和漂白旁路由材料实际经历的步骤产生，不再依赖末端数学反相伪造。
- 显影后的潜影激活比例会随剩余卤化银同步更新，重复显影与部分反转激活遵守同一材料守恒关系。
- 统一彩色流程把最终 RGB 光学密度作为扫描权威输入；旧 CMY 母版继续保留给兼容文件、制版和分层导出。
- 支持彩负反转冲洗、反转片负片冲洗及材料—工艺兼容参数。
- 迫冲/减冲、显影时间与温度、搅动、药水疲劳、定影不足、残银、漏光、显影不均、材料退化和实验性镀银等控制进入正式冲洗链路。

### 冲洗与扫描分离

- 冲洗保存负片或反转正片介质；扫描只读取最终介质，不修改冲洗母版。
- 负片与正片共用透射光源和传感器采集；用户可独立控制片基/色罩去除、反相和可选通道补偿。
- 项目内部使用冲洗后已知片基；外部 raw 依次回退到明确边框样本和画面百分位估计。
- 材料极性只提供建议；保留片基且不反相可直接输出灯台上的负片翻拍或正片观看结果。
- 可选片基参考边框只扩展扫描观察画布，不会写回冲洗母版或 RGB 光学母版。

### 材料与输出

- 增加彩色和黑白反转材料、正片灯台预设及更清晰的中英文预设名称。
- 支持负片/正片 NPZ、scanner/light-table raw、透明介质、16-bit transmission TIFF、制版辅助层和 Layer Pack。
- Layer Pack 是包含介质、预览、raw、透明介质、制版层和 manifest 的完整集合，不是重复的第三套分层定义。
- 主 GUI 的完整流程与只冲洗流程按每次执行创建时间运行目录并保存完整设置快照；只扫描结果默认回到介质目录上一级，并以扫描时间区分不同代次，避免重复运行覆盖旧结果。

### 性能与大图

- `quality`：正式尺寸和完整流程。
- `scaled_fast`：缩小输入尺寸，用于快速试色。
- `reduced_fast`：保留输出尺寸，只降低已声明的内部细节计算。
- 默认舒适区约为 30MP；更高分辨率仍可尝试，但属于 best-effort，并取决于内存、导出内容和处理配置。
- 增加材料形成、扫描和保存分块、受限混合精度、派生数据缓存、资源预检及原子多文件提交。

### 稳定性

- 扫描前后材料母版保持不变，完整流程与分段流程具有系统不变量测试。
- 损坏 NPZ、非法 metadata、NaN/Infinity 和批处理内部同名冲突会明确失败；GUI 的不同执行代次由运行目录或时间后缀隔离。
- JPEG/PNG 的八种 EXIF Orientation 和 TIFF 方向统一在输入边界落实到像素，避免部分竖图输出为横图。
- 当前自动化测试覆盖材料池、冲洗、扫描、输出、GUI preset、性能边界和文件回滚。

## 兼容性

- `half_frame_darkroom` 旧 Python 包名和旧 CLI 名称继续作为兼容入口。
- 拆分后的 film/develop/scanner preset 是推荐格式；旧完整 JSON 配置仍可读取。
- `legacy_density` 只作为显式诊断/回归入口保留，不再是默认形成路径。
- 建议在升级前备份自定义 preset 与重要电子介质文件。

## 当前限制

- 暂不直接读取 DNG 或相机私有 RAW；建议先导出高质量 TIFF、PNG 或 JPEG。
- 正片/反转流程仍标为 experimental；外部实物与实验室验证尚未完成。
- 超过 30MP 的工作负载不能保证在所有电脑上顺畅运行。
- Windows 便携包没有代码签名，可能触发 SmartScreen 提示。
- 当前 Tk GUI 在部分 Windows 系统上拖动复杂窗口时可能有黏滞感，但不会改变处理结果。
